# Spotifm v3 auth/config vertical slice handoff

Goal: modernize `waveplate/spotifm` enough to explore a PJarvis FM path without depending only on Spotify username/password login.

Repo: `/opt/data/work/spotifm` on branch `develop`.

Guardrails:
- Preserve user work. Check `git status --short` first.
- Do not commit or push.
- Do not print, create, or store real Spotify/Discord credentials.
- Do not edit config files with real secrets.
- Do not implement fake tests that only satisfy coverage. Tests must import real functions and validate behavior.
- Do not attempt live Spotify auth in unit tests. Keep network auth behind a thin boundary.

Required TDD scope:
1. Add importable config/auth parsing functions in `src/config.rs` or a new module.
2. Add tests first. They must fail before implementation.
3. Tests should cover real behavior:
   - legacy config with `user` + `pass` parses as a legacy password login mode.
   - new config with a token/session-cache path parses as a non-password login mode.
   - invalid config with neither legacy password nor token/session-cache returns a validation error.
   - bumper index initialization still happens after parsing.
4. Run the specific test and record RED failure.
5. Implement minimal production code.
6. Run specific test, `cargo test`, and `cargo check`.

Implementation preference:
- Introduce an enum such as:
  - `SpotifyLoginConfig::Password { user, pass }`
  - `SpotifyLoginConfig::SessionCache { path }` or `AccessToken { token }` if supported by local librespot APIs.
- Keep compatibility with existing `config.json.example` shape.
- If librespot does not support OAuth/access-token session creation directly, still add validated config shape and leave session creation as explicit TODO/unsupported error rather than pretending it works.
- Refactor `create_session` to call an importable function that chooses login mode, but only password mode may remain implemented for now.

Validation:
- `cargo test <specific config test> -- --nocapture`
- `cargo test`
- `cargo check`

Report:
- Files changed
- Tests added
- Commands run and results
- Remaining limitation: whether live OAuth/session-cache login is implemented or only config-ready
